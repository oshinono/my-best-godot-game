# GDD — Cozy Merge Cafe (рабочее название)

Merge-игра 2D, сеттинг «уютная кофейня, где работают коты». Godot 4.4, GDScript, портрет.

---

## 1. Обзор

| Параметр | Значение |
|---|---|
| Жанр | merge + casual meta (декор, коллекции) |
| Платформы | iOS 14+, Android 7+ |
| Ориентация | портрет (1080×1920 ref) |
| Движок | Godot 4.4, GDScript, рендерер `gl_compatibility` (`mobile` не работает в iOS Simulator) |
| Аудитория | 25–55, преимущественно женщины, casual |
| Сессия | 4–6 мин, 4–5 сессий/день |
| Ядро | слияние предметов на поле 4×5 в прототипе (референс 7×8) → заказы → валюта → декор → новые предметы |

**Обещание игроку:** «Собери уютную кофейню мечты вместе с котами».

---

## 2. Кор-луп (30–90 с)

```
тап генератора → предмет L1 → слияние на поле → предмет выше уровнем
     → выполнение заказа кота → монеты + XP → декор / новый генератор
```

Петля удержания: **энергия кончилась** → rewarded-реклама / IAP / ожидание → возврат.
Петля прогресса: **уровень кофейни** → новые генераторы, слоты заказов, зоны, коты.

---

## 3. Игровое поле

- Сетка **7×8 = 56** клеток (референс дизайна).
- **В прототипе сетка уменьшена до 4×5 = 20** (`Config.board_width` / `board_height`) — клетки и предметы крупнее (~155 px при портрете 720×1280). Возврат к 7×8 — только правкой Config.
- Drag-and-drop предмета на предмет **того же уровня** → предмет следующего уровня (слияние).
- Дроп на пустую клетку → перемещение. Дроп на другой уровень → возврат в исходную.
- Ряды/колонки **не сдвигаются** (это не match-3) — чистая merge-механика.
- Автослияние и авто-сортировка — **не в MVP**.
- Поле не скроллится: всё влезает в экран.
- **Продажа — тапом по предмету.** Тап (палец сместился не больше `Board.TAP_SLOP` = 14 px) открывает затемнение и карточку рядом с предметом: название, подсказка, если такой предмет ждут заказы, и кнопки «🪙 Продать за N» / «Отмена». Карточка зажата в пределы экрана с учётом safe area.
- Цена продажи — `_sell_price(data)` = `Chains.sell_value(...)` × `Config.sell_value_mult` (0.6), см. `docs/economy.md`. Массовая продажа — «Продать всё поле» в настройках (⚙), идёт тем же путём.
- Закрытие меню: «Отмена» или тап по затемнению; пока меню открыто, поле ввод не получает.
- **Дроброс мимо поля ничего не продаёт:** предмет возвращается на место, статус — «Продажа — тапни по предмету».

## 4. Генераторы

Тап генератора создаёт предмет **L1** соответствующей цепочки. Тап стоит энергию.

Генераторы живут **прямо на поле**: под сеткой полоса из трёх прямоугольников, в каждом — название цепочки и цена в энергии (у закрытого — требуемый уровень). Отдельного попапа нет. Полоса занимает `Board.GEN_STRIP_RATIO` (12%) высоты полосы поля; предметы на генераторы не кладутся — это не клетки.

| Генератор | Открытие | Цепочка | Стоимость тапа |
|---|---|---|---|
| Эспрессо-станция | с начала | Кофе | 1 энергия |
| Витрина выпечки | Ур. кофейни 4 | Выпечка | 1 энергия |
| Цветочный горшок | Ур. кофейни 8 | Цветы | 1 энергия |

В MVP у генератора **нет отдельного кулдауна** — гейт только энергия.
После лонча: у генератора появляются заряды (накапливает до N, регенерирует), премиум-генераторы дают L2–L3 старт.

## 6. Энергия

- `energy_max = 100`, регенерация `+1 / 60 c` (значения из `Config`).
- Оффлайн-регенерация **до максимума**, без отдельного капа оффлайна в MVP.
- Источники: время, rewarded-реклама (+15), daily reward, IAP-пакеты.
- При 0 энергии → экран энергии: таймер до следующей единицы, rewarded, кнопка пакета.

**Реализовано (прототип).** Экран — `scripts/ui/energy_popup.gd`, открывается из `_on_energy_not_enough` и при неудачном тапе генератора. Показывает «⚡ N/M · до +1 через T с» (тикает раз в секунду), кнопка rewarded («⚡ +15 за рекламу») с суточным лимитом `rewarded_energy_daily_cap` (счётчик в save: `rewarded_energy_day`, `rewarded_energy_count`). Rewarded дёргается через `Ads.show_rewarded("energy", {"energy": amount})`; при `use_real_ads = false` заглушка сразу эмитит `rewarded_earned`.

## 7. Заказы

- Слоты заказов: **2** с начала, 3-й на ур. кофейни 6, 4-й на ур. 12.
- Кот-клиент просит **1–2 предмета** из открытых цепочек.
- Награда: `coins = 2 × Σ sell_value`, `XP = 50% coins`, шанс гема (~10%).
- Жёсткого таймера **нет**. Есть бонус за скорость: **×1.5 монет**, если выполнить < 20 мин.
- Обновление заказа: бесплатно раз в 30 мин, иначе 5 гемов.
- Событие «все заказы выполнены» → бонусный сундук.

**Реализовано (прототип).** В заказе живёт `created_at` (unix-время). `OrderManager.reward_for(order)` считает `coins = round(compute_coins × bonus)`, где `bonus = order_speed_bonus` (×1.5), если от создания прошло ≤ `order_speed_window_sec` (20 мин), иначе ×1.0; там же считается `seconds_left`. Панель заказов пересобирается раз в секунду (`_on_tick`) и показывает `⏱ M:SS` до конца бонуса; по истечении таймера бонус автоматически 1.0. У каждого слота — кнопка реролла (`_on_order_reroll`) за `order_reroll_cost_gems` (5💎); бесплатный реролл раз в 30 мин пока не реализован. Гем за заказ: `randf() < gem_chance_order` (10%) → `+1💎` в событии `order_completed` (`gems`, `bonus`). `OrderManager.replace(index)` заменяет заказ (используется рероллом и тестами).

## 8. Мета

### 8.1 Кофейня (декор)
- Вид 2.5D сверху, комнаты: зал → кухня → терраса → сад.
- Покупка мебели за монеты → +XP и **уровень кофейни**.
- Уровень кофейни гейтит: генераторы, слоты заказов, зоны, котов.

### 8.2 Коты
- 12 котов, у каждого роль (бариста, официант, гость-критик, пекарь…).
- Открытие: уровень кофейни + условие (N заказов / найден в сундуке).
- Альбом: карточка (имя, редкость, история), 3 редкости.
- Пассивный бонус: **+5% монет за заказ** за каждого кота, суммируется.

### 8.3 Ежедневная награда
- 7-дневный стрик: монеты / гемы / энергия; 7-й день — «котовый сундук».
- Пропуск дня → стрик сбрасывается на 1 (мягкий режим — не в MVP).

### 8.4 FTUE
| Шаг | Время | Действие |
|---|---|---|
| 1 | 0:00 | тап генератора → слияние |
| 2 | 0:45 | первый заказ и его выдача |
| 3 | 3:00 | покупка первого декора |
| 4 | 5:00 | пустая энергия → **rewarded**, не IAP |
| 5 | 6:00 | открытие альбома котов |

IAP впервые показываем **не раньше** 2-й сессии.

**Реализовано (прототип).** Мета живёт в автолоаде `Meta` (`scripts/autoload/meta.gd`), таблицы контента — в `scripts/data/meta.gd`, интерфейс — попап `scripts/ui/meta_popup.gd` (кнопка `🐱` в HUD левее `⚙`, четыре вкладки: «🎁 День», «🐱 Коты», «🛋 Декор», «🏠 Карта»).

- **Декор (8.1).** 27 предметов (`DECOR` в `scripts/data/meta.gd`): зал, кухня, терраса, сад; цена от 120 до 2600 🪙, XP от 40 до 320. Покупка (`Meta.buy_decor`) списывает монеты, добавляет XP через `Progress.add_xp()` — то есть уровень кофейни = уровень игрока (отдельного счётчика нет). Рисованного вида 2.5D нет: комнаты показаны схематично во вкладке «🏠 Карта» (`ROOMS` — зал/кухня/терраса/сад с цветом пола, `SLOTS` — 28 точек `{id, room, tx, ty, w, h}`).
- **Расстановка мебели (8.1).** Купленный предмет ставится в слот своей комнаты: на вкладке «🏠 Карта» полка непоставленного (`Meta.unplaced_decor()`), тап по предмету → подсветка свободных слотов (`➕`), тап по слоту → `Meta.place_decor(decor_id, slot_id)`; тап по занятому слоту снимает предмет (`Meta.clear_slot(slot_id)`). Проверки: предмет куплен, слот существует, комната совпадает (`Сюда можно ставить только: %s`); при переносе предмет уходит из старого слота. Состояние — `placed: {slot_id: decor_id}`, ключ сейва `decor_placed` (мусор чистится при загрузке); сигналы `placement_changed(slot_id, decor_id)`, в попапе — `place_requested`/`clear_slot_requested`. Реальные спрайты мебели позже: каталог `assets/decor/` пуст, слоты подписаны коротким именем (`decor.short`).
- **Коты (8.2).** 12 котов (`CATS`): редкости common/rare/epic, у каждого имя, роль и история. Открытие — при уровне кофейни и числе выполненных заказов (`Meta.check_cat_unlocks(_orders_done)`, ключ сейва `orders_done`); эпические коты падают из котового сундука (7-й день стрика). Альбом — список карточек во вкладке «Коты». Пассивный бонус: `Meta.cat_bonus()` = `1 + открытых × Config.cat_bonus_per_cat` (0.05), применяется к монетам заказа в `_on_order_pressed()` (в статусе показывается `🐱+N%`).
- **Ежедневная награда (8.3).** 7-дневный стрик (`DAILY_REWARDS`): дни 1-6 — монеты/энергия/гемы, день 7 — котовый сундук; если все коты из сундуков уже открыты, выдаётся `Config.daily_chest_gems` (15💎). Пропуск дня или завершённый стрик сбрасывают его в начало (мягкий режим не делаем). Ключи сейва: `daily_streak`, `daily_last_day`; готовность к получению — `Meta.can_claim()` (в HUD у кнопки `🐱` появляется точка), сама выдача — `Meta.claim()`.

Событие `shop_open` отправляется при открытии попапа меты; `daily_reward_claim`, `cat_unlocked`, `decor_purchased`, `decor_placed` — при соответствующих действиях (см. `docs/analytics-events.md`).

## 9. Прогрессия

- Уровень игрока: `xp_next(n) = round(50 × n^1.5)`.
- В MVP — 20 уровней, дальше контент-обновления.
- Гейты: генераторы (ур. 4, 8), слоты (6, 12), зоны, коты.

**Реализовано (прототип).** Уровень: `Progress.add_xp()`, порог `xp_next(n)`, сохранение в `SaveManager`; при апe — событие `level_up` и текст «Открыто: …». FTUE пишется через `_ftue_step(step)` — флаг `ftue_<step>` в сейве + событие `ftue_step`: `opened`, `first_generator`, `first_merge`, `first_order`, `out_of_energy`.

## 10. Монетизация

### Rewarded (главный источник ARPDAU)
| Оффер | Награда | Лимит |
|---|---|---|
| Энергия | +15 | 5/день |

**Реализовано (прототип).** Энергетический rewarded: `rewarded_energy_amount` (15) и `rewarded_energy_daily_cap` (5/день). Ключи сейва `rewarded_energy_day` (номер суток = unix/86400) и `rewarded_energy_count`; при исчерпании лимита кнопка в попапе энергии выключается. Вызов — `Ads.show_rewarded("energy", {"energy": amount})`, при `use_real_ads = false` заглушка сразу эмитит `rewarded_earned`. Остальные офферы (×2 за заказ, мгновенные тапы, сундук) — ещё нет.
| ×2 награда за заказ | удвоение монет | без лимита |
| Мгновенные тапы | 10 тапов без энергии | 3/день |
| Бесплатный сундук | 5–20 гемов | 1/день |

### Interstitial
- Только между действиями, не чаще 1 раза / 3 мин.
- Отключены в первые 3 сессии и во время FTUE.

### IAP
- Стартовый пак, гемы, монеты, энергия, **копилка** («без рекламы» — как опция).
- Без gacha/loot-box со ставками в MVP (требования сторов).

## 12. Тех-заметки

- Автолоады (уже есть): `Config`, `SaveManager`, `Progress`, `Energy`, `Analytics`, `Ads`, `Iap`, `Haptics`, `Meta`.

- Аналитика — **PostHog** через HTTP `/batch/` (`scripts/autoload/analytics.gd`), ключи в `Config`, детали и список событий — `docs/analytics.md`.
- Рендерер — `gl_compatibility` (Mobile не работает в iOS Simulator). Проверка iOS без Apple-аккаунта: симулятор, StoreKit Testing, тестовые AdMob — `docs/ios-testing.md`.

## 15. Аудио

- **Музыка:** 2–3 лупа — кофейня днём, уютный/вечерний, меню. 60–90 с, зациклены, OGG Vorbis (Godot импортирует в `OggVorbis` с флагом loop), цель ≤1.5 МБ на трек.
- **SFX (~20):** тап генератора, слияние, слияние высокого уровня, провал слияния, заказ принят, заказ выполнен, монеты, XP, level up, гем-дроп, rewarded старт/финиш, покупка, ошибка, кнопки (2), открытие сундука, разблокировка кота, daily, пустая энергия.
- **Источники:** freesound.org, Kenney (CC0), Pixabay. ⚠️ Проверять коммерческую лицензию и хранить `attribution`-файл.
- **Шины:** Master → `Music`, `SFX`, `UI` через `AudioServer`. Шина SFX глушится (или приглушается) во время rewarded-рекламы — обязательно.

**Реализовано (прототип): тактильный отклик вместо звука.** Звука в прототипе нет ни в каком виде — вся обратная связь тактильная (решение владельца продукта). Автолоад `Haptics` (`scripts/autoload/haptics.gd`) поверх нативного iOS-плагина `ios/plugins/haptics/` (синглтон `HapticsIOS` поверх `UISelectionFeedbackGenerator`; нативный `impact()` в плагине остался, но игрой не вызывается). API — один отклик: `Haptics.selection(strength = Strength.LIGHT)` — серия тиков `UISelectionFeedbackGenerator` с `enum Strength { LIGHT, MEDIUM, HEAVY }` (1, 2 и 3 тика с паузой 30 мс; у selection нет параметра силы, поэтому градация количеством); плюс `Haptics.prepare()`, `Haptics.mute_for_ads(true/false)` (глушит вибрацию на время rewarded и interstitial — обязательно), `Haptics.set_enabled(value)`, `Haptics.enabled`. Мелкие события (кнопки, тап генератора, монеты, старт rewarded), провалы и дроп гема — `selection(LIGHT)`; обычные (слияние, заказ, daily, покупка декора) и «мало энергии» — `selection(MEDIUM)`; значимые (level up, сундук, покупка за деньги, новый кот) — `selection(HEAVY)`. Свойства реализации: только мобилка, начало серии троттлится 40 мс, тики внутри серии идут без гейта с паузой `TICK_GAP = 30 мс`. Готовые `haptics.debug/release.xcframework` лежат в репозитории, флаг `plugins/Haptics=true` включён в iOS-пресете. На Android/десктопе бинаря нет — работает запасной `Input.vibrate_handheld(ms, amplitude)` по таблице `FALLBACK` в автолоаде; идеальный Android-тик (`CLOCK_TICK`) требует отдельного Java-плагина и пока отложен. Тумблер «📳 Вибрация» — в настройках (ключ сейва `haptics_enabled`, старый `audio_haptics` читается как фолбек). Сборка xcframework, установка и ограничения (в симуляторе вибрации нет) — `docs/haptics.md`.

## 16. Локализация

- **Старт:** RU + EN. Далее по трафику: DE, FR, ES, PT-BR, TR, JP, KR.
- **Godot:** встроенная система переводов; строки в CSV → `.translation` (в `.gitignore`).
- **Правила:** не склеивать строки из кусков; множественные числа через `tr_n`; закладывать запас ширины (EN +30%, DE +35%); числа/валюты через `String.num` и локаль.
- **Шрифт:** один rounded sans (Nunito / Baloo 2 / Quicksand) с кириллицей + латиницей; CJK — отдельным subset позже.
- **Тест:** псевдолокаль (удлинить строки, обернуть в скобки) для ловли обрезки UI.
- ⚠️ Стор-листинги локализуются отдельно, не из игровых строк.

## 17. Push-уведомления

- **Разрешение** — только после первого значимого действия (первое слияние / первый заказ), не на старте.
- **Типы:** «энергия восстановилась» (через полный запас), «кот скучает / заказ ждёт» (24 ч), «daily reward готов» (23 ч), «новый кот в альбоме» (ивент), re-engage на 3-й и 7-й день молчания.
- **Частота:** максимум 1/день; отключаемо в настройках.
- **Реализация:** OneSignal или нативный плагин. ⚠️ Реальные iOS-пуши требуют подписи и APNs (см. `docs/ios-testing.md`); в симуляторе — только обработка пейлоада через `xcrun simctl push`. ⚠️ На sideload-сборке (бесплатный Apple ID через Sideloadly) **пушей нет вообще** — канал проверяем на Android, в MVP закладываем локальные напоминания (`UNUserNotificationCenter`).

## 18. Бустеры

В MVP не обязательны, но заложить в шоп как гем-слив:

| Бустер | Эффект | Цена |
|---|---|---|
| Хаммер | Удалить один предмет с поля | 5💎 |
| Шафл | Перемешать предметы по полю | 10💎 |
| Магнит | 3 случайных L1 в свободные клетки | 15💎 |
| Слот +1 | Временный слот заказа до открытия по уровню | 15💎 |

⚠️ Бустер не должен превращаться в «pay-to-skip»: не больше 1 применения на бустер за сессию.

**Реализовано (прототип).** Ряд кнопок на HUD: `🔨 5💎` / `🔀 10💎` / `🧲 15💎`.
Хаммер включает режим прицела — следующий тап по предмету убирает его; если тап
пришёлся на пустую клетку, бустер отменяется и гемы возвращаются. Магнит берёт
первую разблокированную цепочку. Цены и лимиты — в `Config`:
`booster_hammer_gems`, `booster_shuffle_gems`, `booster_magnet_gems`,
`booster_magnet_count`, `booster_per_session_limit`. Гемы — в сохранении
(`SaveManager.get_value("gems")`), для тестов есть dev-ключ `start_gems`.

## 19. Крайние случаи поля

- Поле заполнено полностью → блокировать тапы генераторов, показать «Нет места» + предложить продажу/бустер.
- Нет доступного хода (нет двух предметов одного уровня и нет места под L1) → разрешить продажу, затем шафл.
- Тап генератора без энергии → экран энергии.
- Слияние на максимуме цепочки (кофе L10) → не сливается, кнопка «В заказ».
- Дроп предмета на генератор → запрещён (генераторы — полоса прямоугольников под сеткой, не клетки; `Board.set_generators()`).
- Сохранение во время анимации слияния → сохранять только финальное состояние, не мид-анимацию.
- Двойное слияние за один кадр → применять последовательно, дожидаться завершения твина.

## 20. Сессионный флоу

1. Boot → `main_menu` (HUD: монеты, гемы, энергия).
2. Пуш / daily → `daily_reward`.
3. `game`: 4–6 мин, 3–4 цепочки слияний, 1–2 заказа.
4. Энергия кончилась → `energy_popup` → rewarded / IAP / выход.
5. `cafe`: покупка декора, level up → новые гейты.
6. `cats_album` / `shop`: раз в 2–3 сессии.

Итог: 4–5 сессий/день, 20–30 мин/день. Возврат — всплески в 8–9 и 19–21 ч (когда энергия восстановилась).

## 21. Доступность

- Тач-таргеты ≥ 48 dp (iOS 44 pt).
- Контраст текста ≥ 4.5:1; состояние не только цветом (уровень — своим артом, у плейсхолдеров без арта пипсами; номера на предметах не показываем).
- Дальтоники: палитра не опирается на пару красный/зелёный, каждый уровень цепочки рисуется своим артом (у плейсхолдеров без арта уровень показан пипсами).
- Масштаб UI: по возможности следовать системному размеру шрифта.
- Вибро: короткий тик при смене значения/выборе, импульс на слиянии, переключатель «📳 Вибрация» в настройках, не на каждом тапе.
- Движение: настройка «меньше анимаций» — отключает тряску и тяжёлые частицы.

## 22. LiveOps (после лонча)

- **Ивенты:** «Кошачий фестиваль» (7 дней, отдельный пул заказов), «Осенняя выпечка» (лимитированный декор), «Праздник котов» (коллекционные коты).
- **Сезонные альбомы:** 5–10 новых предметов в существующие цепочки.
- **Клубы/лидерборды:** только после D30 ≥ 6%.
- ⚠️ LiveOps требует серверной выдачи контента и календаря ивентов — отдельный этап бюджета.

## 23. Риски и митигации

| Риск | Митигация |
|---|---|
| Плагины рекламы нестабильны | План Б: только AdMob rewarded, медиация после лонча |
| Нет бэкенда и A/B | `REMOTE_CONFIG_URL` или PostHog feature flags |
| Слабые устройства | Рендерер Compatibility, лимит частиц, тест на 3–4 старых Android |
| Инфляция экономики | Декор как главный слив, сезонный декор, цены в `Config` |
| Низкий ретеншн | FTUE-воронка в PostHog, daily reward, пуши |
| iOS не монетизируется (нет аккаунта) | Тесты в симуляторе, метрики с Android как основной площадки |
| Переусложнение архитектуры | Signals + 5 автолоадов, без сторонних фреймворков |

## 24. A/B и серверный конфиг

- **Первые тесты:** цена стартового пака, энергия за rewarded, стартовый лимит слотов, длина FTUE.
- **Механизм в MVP:** `REMOTE_CONFIG_URL` (свой JSON) или PostHog feature flags / remote config (тот же ключ, что аналитика).
- ⚠️ Никаких A/B до 1000 DAU — мощности не хватит, получится шум.
- Каждый эксперимент: гипотеза → метрика → длительность → решение (KPI — в `economy.md`).
